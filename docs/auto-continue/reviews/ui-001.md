## 1. Findings

### MINOR-1 — 弹窗遮罩用硬编码 `rgba`，未走 token（主题适配缺口）

- **位置**：`DetailDialog` 最外层 overlay 的 `style.background: 'rgba(0, 0, 0, 0.34)'`。
- **依据**：
  - 范本 `dsh-ability-strip/lib/client.js` 的 `Modal` 用 `TOKEN.mask`（`var(--dsw-alias-bg-mask-1)`）作为遮罩背景，其文件头注明"tokens are the only styling contract"。
  - `--dsw-alias-bg-mask-1` 在 theme 真相源 `dsh-client-ui-theme/lib/client.js` 的 body token 定义块中出现，是真实存在的 alias token。
  - `design-final.md` §7 T2 / `requirement.md` §5 T2 要求客户端"只用 `--dsw-alias-*` token"。
- **推演链**：遮罩颜色写死为固定 rgba → 切换深浅主题时遮罩不会随主题变化 → 与宿主自带弹窗的遮罩观感不一致。这是观感一致性问题，不是加载/功能问题：0.34 的黑在深浅主题下都可见、可关闭。
- **影响**：主题切换时弹窗遮罩"不跟手"，属打磨项。
- **建议**：遮罩背景改用 `var(--dsw-alias-bg-mask-1)`，与范本 Modal 对齐。（`boxShadow` 用 rgba 范本同样如此，不属此问题。）

### MINOR-2 — `DetailDialog` 未做 Tab 焦点约束（focus trap）

- **位置**：`DetailDialog` 的 `useEffect`（依赖 `[open, onClose]`）——只在 `keydown` 里处理 `Escape`，聚焦 `dialogRef.current` 并在清理时还原 `previous`；没有范本 `Modal` 中对 `Tab` 的 first/last 焦点回卷。
- **依据**：
  - 范本 `dsh-ability-strip/lib/client.js` 的 `Modal` 明确处理 `Tab`：查询 `button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])`，在首尾元素间回卷，并声明 `aria-modal` 的键盘所有权。
  - 本实现声明了 `role="dialog"` + `aria-modal="true"`（对辅助技术宣称外部内容 inert），但物理 Tab 仍可能移到遮罩之后的页面元素。
- **推演链**：弹窗打开 → 初始焦点在 dialog、Esc 与还原焦点都正常 → 但连续 Tab 可越过 dialog 焦点到遮罩后面的 dock 按钮/页面控件 → 与 `aria-modal` 语义不一致。当前弹窗内只有 `×` 与底部"关闭"两个可聚焦按钮，影响面有限；Esc/遮罩/按钮三种关闭路径均不受影响。
- **影响**：键盘/读屏用户的焦点 containment 不完整。用户列出的四项（遮罩/×/Esc/焦点管理）中"焦点管理"已部分满足（移入+还原），Tab trap 属完整性补强。
- **建议**：沿用范本 `Modal` 的 `Tab` 回卷逻辑，使焦点留在 dialog 内。

> 说明：以上两条均为"证据充分但影响有限"的 MINOR。按 `code-review-static` 的严重度纪律，不因"想多报几条"而把主观打磨抬成阻断项；其余观察（如关闭按钮无 `:active` 按压反馈、无进场动画）属可接受取舍——无动画对偶发弹窗是合理选择（Raycast 同类做法），不构成 finding。

## 2. 回归防线逐项核对（最重要 · 防再次翻车）

结论：**client id / react-dom / inject / slot / exports 五项全部安全，无 entry 不激活风险。**

| 项 | 结论 | 证据与推演 |
|---|---|---|
| **client id** | ✅ 安全 | `load({ id: 'dsh-auto-continue', ... })` 逐字等于 `package.json` 的 `name`（`dsh-auto-continue`）。事故根因是曾写成 `'auto-continue'`（缺 `dsh-` 前缀）导致 loader 找不到 factory；本次 id 正确。slot cell id `'auto-continue-status'` 按 `incident-001.md` 结论无需等于包名，保持不动，正确。 |
| **react-dom 可用** | ✅ 安全 | 新增 `require('react-dom')` 是客户端可用静态模块，不会 import failed。证据：(1) 范本 `dsh-ability-strip/lib/client.js` 同样 `require("react-dom")` 并用 `ReactDOM.createPortal`，长期工作正常；(2) DSH 自带大量一方客户端包均 `require("react-dom")`（`dsh-client-ui-conversation`、`dsh-client-ui-chat`、`dsh-client-ui-renderer` 等）；(3) `dsh-web-frontend/dist/assets/index-*.js` 的 staticModules 种子映射中显式含 `"react-dom": ...`，说明其在 ModuleLoader 的静态模块表里。`react`/`react-dom` 均非 `@deepseek-ai/*`，符合 T1。 |
| **inject 数组** | ✅ 安全 | 客户端 `inject = ['slots', 'connection']`，与范本 `["slots", ..., "connection"]` 一致，二者都是 Cordis 可门控的真实服务。`apply` 内 `const connection = ctx.connection` 与范本取法相同。注意：check.mjs 静态断言（check.mjs 中 `manifest: name / inject / version`）读的是**宿主** `lib/index.js` 的 `inject`（`agents,sessionPersistence`），与本客户端 inject 是两处，互不干扰，断言不受影响。 |
| **slot 注册形态** | ✅ 安全 | `ctx.slots.inject('conversation.composer.dock', () => ctx.slots.register({ name, id, order, inject: () => ({ load }) }, Component))` 与范本逐字段同构：同一 slot 名 `conversation.composer.dock`、`register` 的 descriptor（name/id/order/inject）+ 组件 二参形态一致。`load: (sessionId, signal) => readStatus(connection, signal)` 签名与范本 `load: (sessionId, signal) => ...` 一致。无会导致 entry 不激活的差异。 |
| **exports.apply / inject** | ✅ 安全 | `exports.apply = apply`、`exports.inject = inject`、`return module.exports` 齐全，与范本（文件尾同三行）一致；CJS 工厂形态、`Object.defineProperty(exports, Symbol.toStringTag, ...)` 未变。`factory: (require) =>` 仍为 lazy-CJS。 |

补充：`readStatus` 对 `connection?.rpc?.call === undefined` 返回 `{ error }` 且全程 try/catch，永不抛出；故 `StatusChip` 里 `load(...).then(...)` 无未捕获拒绝路径。`connection` 未注入时走 error 分支而非崩溃。

## 6. UI 质量评价（emil-design-eng）

整体：呈现方式较旧版有实质优化——从"状态码文案"收敛为图标+数字的极简 dock，详情按"概览条 + 分组列表"组织，id 截断、tabular 数字、层级字号都在位，属 refined minimalism 而非廉价默认样式。以下为按 emil 评审格式的逐项对照（`Before` = 当前实现，`After` = 建议打磨；仅前两行对应正式 MINOR，其余为已达标项，列出以供确认）：

| Before | After | Why |
| --- | --- | --- |
| 遮罩 `background: rgba(0,0,0,0.34)`（硬编码） | `background: var(--dsw-alias-bg-mask-1)` | 范本 Modal 用主题 mask token；随主题统一遮罩观感（MINOR-1） |
| 弹窗只处理 `Escape`，未约束 `Tab` | 增加范本 Modal 的首尾 Tab 回卷 | `aria-modal` 宣称外部 inert，焦点应留在 dialog 内（MINOR-2） |

| id 用 `<code>` + `ellipsis` + `minWidth:0` + `title=id` | 保持不变 | 长 id 截断且有 tooltip，处理到位 |
| 字号层级 13/18/11/10px + 600 字重 | 保持不变 | 标题/数值/label 层级清晰，读数优先 |
| `maxHeight:'80vh'` + `overflow:'auto'` | 保持不变 | 长列表可滚动、不溢出视口 |

补充：`zIndex: 2147483000` 与范本一致；留白（summary gap 20 / padding 10×12、header marginBottom 12、行 padding 5×0）与对齐（flex baseline、space-between）自洽；空态、错误态、未扫描态各有明确文案，无"把读取失败伪装成 0"的诚实性问题。

## 7. React 正确性

- **Hooks 顺序**：`DetailDialog` 的 `useRef`/`useEffect` 均在 `if (open !== true) return null` 之前调用；`StatusChip` 全部 hooks 在 return 前调用 → 无条件 hooks，顺序稳定。✅
- **useEffect 依赖/清理**：`StatusChip` 的 `[load]` 用 `alive` 守卫避免卸载后 setState，返回清理函数置 `alive=false`；`DetailDialog` 的 `[open, onClose]` 清理事件监听并还原焦点。✅
- **onClose 稳定性**：`close = useCallback(() => setOpen(false), [])` 为稳定引用，父组件每次渲染不产生新 `onClose`，避免 effect 反复重跑。✅
- **portal**：`ReactDOM.createPortal(..., document.body)` → 脱离 dock 的 overflow 裁剪，层级正确。✅
- **key 唯一**：`resumed` 以 session id 为 key；`skipped` 以 `${id}-${index}` 为 key（index 兜底重复 id）。✅
- **事件冒泡**：遮罩 `target===currentTarget` 判定；Esc 用 capture + `stopPropagation`，不误触页面。✅
- **挂载抛错路径**：`data` 初始为 `null` → `scan` 为 `undefined` → `resumed/skipped` 回落空数组 → count `'—'`、弹窗显示"尚未完成"；`readStatus` 全程吞异常返回 `{error}`；`connection` 缺失走 error 分支。未发现挂载即抛的路径。✅
