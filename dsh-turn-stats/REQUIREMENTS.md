# 需求说明书：状态栏统计（v1「本轮」→ v2「最近一次模型调用」）

> 本文件只写**需求**，不写实现方案。实现方案另见后续文档（需要时再写）。
> 写于 2026-11-11，基线版本 dsh `0.2.2-rc.1`、profile `web`。
> ⚠️ **口径已在同日修订一次，见 §6**。§1–§5 保留 v1 原文以保留决策痕迹，凡与 §6 冲突处以 §6 为准。

## 1. 背景

Web 状态栏（输入框下方那两颗药丸）显示两项统计：

- 输出速率（tok/s）
- 缓存命中率（%）

**现状**：这两个数都是**整个会话累计**的值——速率是「会话至今输出 token ÷ 会话至今解码耗时」，缓存命中是「会话至今缓存读取 ÷ 会话至今全部计费输入」。

**问题**：会话越长，这两个数越不能反映当前这一次推理的实际表现。长会话里看数值基本不动，无法据此判断"这一次请求是快是慢、有没有吃到缓存"。

**目标**：这两项统计改为**当前轮次（本轮）**的值。

## 2. 需求

### 2.1 统计口径

> ⚠️ 本节的「本轮」已由 §6 修订为「最近一次模型调用」。两项统计的**算式不变**，变的是求和范围。

- **速率**：显示**本轮**的输出速率，不是会话累计。
- **缓存命中**：显示**本轮**的缓存命中率，不是会话累计。

### 2.2 显示形式

- 保持现有的**紧凑样式**（就是现在这两颗药丸的样子）。
- 不要变成"详细模式"那种可点开的详情卡。

### 2.3 位置

- 仍在现在这两颗药丸的位置，不新增第三颗，不移动。

### 2.4 数据时机

- 用**服务端返回的**本轮数据，不要在前端另外推算或猜测。
- 本轮结束后数值应当更新到本轮的实际值。

### 2.5 边界

- 只读：插件不写任何会话数据、不改配置、不改模型设置。
- 没有数据时（例如本轮刚开始、还没有任何输出）保持安静，不显示 0 或占位数字。
- 不影响其它功能：除了这两颗药丸，不改动界面任何其它部分。

## 3. 验收标准

1. 会话开始前几轮，数值应明显随每轮变化（而非从第一条消息起就不动）。
2. 一轮之内连续两轮请求时，第二轮的数值应体现第二轮自身的情况。
3. 外观与现在完全一致，只是数字口径变了。
4. 不出现新的报错、告警或界面异常。

## 4. 不在范围内

- 不改会话标题、模型选择、权限等其它界面元素。
- 不做"实时逐 token 刷新"（这是另一个需求，本期不做）。
- 不写文档、不写测试用例（本期只交付插件本体）。

## 5. 待确认

- 「本轮」的边界：以一轮用户消息到该轮回答结束为准（含轮内工具调用与多次推理请求）。若产品上希望"不含工具调用"，需在开发前说明。

## 6. 需求变更 v2（2026-11-11，用户提出并已确认）

v1 上线后用户提出：一轮可能持续非常久，等 `turn/end` 才出数等于看不到，希望"执行很少的几步就可以看到数据"。

| 项 | v1 | **v2（现行）** |
|---|---|---|
| 统计范围 | 当前轮次（含轮内多次模型调用） | **最近一次模型调用** |
| 更新时机 | 轮结束（`turn/end`）定格 | **每次模型调用结算时**即更新 |
| 取代关系 | —— | 仅取代 §2.1 的求和范围与 §2.4 第 2 条；**§2.2 显示形式、§2.3 位置、§2.4 第 1 条（服务端下发、不前端推算）、§2.5 边界全部继续有效** |

### 6.1 为什么能做到，而"实时"做不到

一次模型调用的用量与解码耗时是随该调用的结算事件一起落盘的，所以"调用一结束就出数"不需要任何新数据源；而**流式进行中的那次调用**在结算前没有任何已提交的用量可证——那仍然属于 §4 排除的"实时逐 token 刷新"，本期仍不做。

### 6.2 代价（用户已知悉并接受）

- **速率会更抖**：单次调用的样本量小，一步只吐几百 token 时算出的速率天然比轮平均噪声大。
- **缓存命中更常显示 0%**：单次调用没命中就是 0，不再被同轮其他调用的命中摊平。
- 名字与投影 key 仍是 `dsh-turn-stats` / `turnStats`（改 key 要多出一条迁移与共存路径，不值）。**口径以本节为准，不以名字为准。**

### 6.3 v2 的验收追加

在 §3 之上加一条：发出一个会走多步的请求，在**第二个 step 结算后**（不必等轮末）数值就应变成该次调用的值；此时该值与整轮合计**不相等属正常**，交叉核对的对象是「那一次调用的用量」，不再是「那一轮的合计」。

### 6.4 文案长度约束（同日追加，用户提出）

状态栏空间珍贵，药丸上的字数能省则省：

| 药丸 | v1 | **v2** |
|---|---|---|
| 速率 | `210 tok/s` | `210 tok/s`（单位保留：去掉 `tok/s` 会与宿主留下两种说法） |
| 缓存 | `缓存命中 72%` | **`缓存 72%`**（en：`Cache 72%`） |

口径的含义不占药丸版面：数据库图标 + 数字本身已经说明"这是缓存"，"哪一次调用"由插件说明文案（`title` / `description`，显示在插件管理而非状态栏）承载，改称「最近一次调用」。截断时的悬停提示仍是全文，规则不变。

### 6.5 两条裁决（同日，用户拍板，覆盖评审意见）

- **`0 tok/s` 允许显示，不算违反 §2.5。** §2.5 禁的是**没有数据时拿 0 当占位**；而一次已结算调用报出 0 输出 token，或真实速率低于 0.05 token/s（`formatTokensPerSecond` 只保留一位小数）印成 `0`，都是**测出来的 0**——是主张，不是占位。因此发布端与渲染端**都不加** `decodeTokens > 0` 门槛，`ActivityPill` 只保留 `decodeMs > 0`（没有解码窗口=没有速率可言）。后续评审若再按 §2.5 提这条，引用本节，不要改代码。
- **重启照 [INSTALL.md §15.1](../INSTALL.md#151-重载与重启官方明文决定改完要不要重启) 执行，"未重启也曾生效"的悬案不再调查。** 用户接受每次宿主半边变更都付一次重启（代价 = 一次会话中断，实测会话可存活）。那条观察连同反证仍留在 HANDOFF「安装与实测证据（0.2.0）」第 2 条备查，但**操作口径不因它改变**，也不再作为待办追踪。
